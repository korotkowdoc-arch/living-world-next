# LIVING WORLD NEXT

Новый проект интерактивных миров для iPhone. Старый `korotkowdoc-arch/living-world` остаётся нетронутым.

**Актуальная версия исходников: v0.12.1.**

**Идея:** создание мира за одно описание, настройка условиями на обычном языке, истории в ChatGPT, независимые персонажи, реальная причинность, отношения без автоматического примирения и сохранение по действующей ветке.

## Работающие системы

- Mobile-first веб-интерфейс `/public` (никакого Windows-приложения, компиляция не требуется).
- Авторизация Supabase email/password, обновление сессии, owner-only RLS, создание/удаление миров.
- Генезис из произвольного описания без обязательных таблиц NPC; текст хранится дословно.
- Постоянные принципы поведения и свободные пользовательские директивы; правки, отключение и журнал изменений без переписывания прошлого.
- Атомарная запись сцен с `expected_head` и `request_id`, альтернативные ветки, история только действующей цепочки. Миграция v0.2 добавляет атомарную правку «На это» с сохранением точного префикса и его исходных подтверждённых событий.
- Типизированные изменения персонажей, отношений, знаний, денег, имущества и обязательств с цитатами из сцен. Запреты на примирение и на уважение теперь независимы. Новые условия не пересматривают сыгранные сцены задним числом.
- Создание мира и исходных закреплённых запретов выполняется одним SQL RPC: нет частично созданного мира при сбое второго запроса (миграция 003).
- Полнотекстовый (дословный) поиск по **всей действующей ветке**, включая очень старые сцены: новый SQL RPC и MCP `search_story_memories`.
- История персонажа с источниками подтверждённых событий: новый SQL RPC и MCP `get_actor_history`, просмотр исходной сцены.
- Резервный JSON-экспорт **всех веток** со сверкой целостности SHA-256, проверка архивного файла без загрузки на сервер. Восстановление в отдельный мир поддерживается миграцией 006 с указанными ниже ограничениями.
- Необязательная литературная диагностика повторяющихся штампов инициативы/примирения (не автоматическая цензура).
- Устанавливаемая на iPhone PWA-оболочка. Офлайн-кэш хранит только публичные статические файлы, **не** личные истории или OAuth.
- GitHub Actions проверяет JavaScript и тесты после каждого push/PR.
- OAuth 2.1 protected-resource metadata, consent-экран, проверка подписанного Supabase OAuth-токена через Auth и MCP-инструменты чтения/записи. **Сервер опубликован и отдельный OAuth-клиент зарегистрирован; реальный обмен токена ChatGPT и запись сцены пока НЕ подтверждены.**
- Полная структурированная память действующей ветки через `nw_active_memory_page`, без скачивания тел сцен. Каждая страница привязана к версии вершины ветки; лимит 50 000 сцен явно обозначается как неполнота.
- Цели NPC через события `plan` с жизненным циклом, источниками, без автоматического завершения или скрытого фонового ИИ. `get_npc_agency` и экран персонажей показывают планы.
- Повтор сохранения с прежним `request_id` проверяется SQL по содержанию и источнику, даже если после сохранения изменилась активная ветка. В браузере ID запроса детерминирован по тексту, ожиданию вершины и времени; при потере сети проверяется квитанция.
- Получение старых сцен через MCP помечает, относится ли сцена к **действующей** ветке: отменённые варианты не становятся фактами в новом продолжении.

## Автоматическое подключение Supabase

Новый сайт уже знает URL базы и её **публичный** publishable key (`public/lib/public-config.mjs`). В iPhone Safari не нужно вводить длинный URL и ключ: достаточно войти в Supabase-аккаунт. Это не секретный ключ, правила RLS продолжают защищать личные истории; `service_role` никогда не публикуется. При необходимости сервер можно переопределить в интерфейсе, а старые сохранённые настройки браузера имеют приоритет.

## Быстрый просмотр локально (только для разработки)

```powershell
npm test
npm run check
npm run dev
```

Открой `http://127.0.0.1:4173`. На телефоне после публикации используется HTTPS-адрес Cloudflare Pages. Локальный сервер не нужен для постоянной игры.

## Сборка и публикация

Компиляция для веб-клиента не нужна — готовые файлы находятся в `public/`. Для начала работы с облачной базой: последовательно применить `supabase/schema.sql` и `supabase/migrations/001_story_controls.sql` в Supabase SQL Editor, затем развернуть `public/` на Cloudflare Pages. Подробности: `docs/DEPLOY.md`.

Для **первичной публикации в уже созданный пустой GitHub-репозиторий** из распакованной папки в Windows (при уже настроенном `gh`):

```powershell
git pull --ff-only; npm test; npm run check
```

Скрипт сохранён в UTF-8 **с BOM** для совместимости с Windows PowerShell 5.1. Его можно запускать из любой папки по полному пути; он сам переходит в каталог распакованного проекта.

Скрипт использует только `korotkowdoc-arch/living-world-next`, публикует в него лишь когда он пустой, не делает принудительных перезаписей и не трогает старые репозитории. Никаких приватных API-ключей в коде нет. Публикация отдельно от развёртывания на Pages, Supabase и Worker.

## Важно о ChatGPT

Сценаристом остаётся ChatGPT с пользовательской подпиской. Этот репозиторий не вызывает платный OpenAI API. `worker/mcp.mjs` поддерживает OAuth 2.1 resource metadata, проверку пользовательских JWT и MCP-инструменты, а `/oauth/consent.html` — страницу выдачи разрешения. Supabase Auth выполняет сам OAuth code+PKCE обмен. OAuth Server и отдельный OAuth-клиент существуют. До реальной проверки токен-обмена и сохранения сцены из ChatGPT автоматическое сохранение считать работающим нельзя. Резервный импорт сцен в интерфейсе позволяет проверить базу и ветки уже сейчас.

`docs/ARCHITECTURE.md` — договорённости о дальнейшей разработке. `STATUS.md` — единый актуальный план.

## v0.3: обязательное обновление базы

После `supabase/schema.sql` и `supabase/migrations/001_story_controls.sql` выполни **`supabase/migrations/002_memory_retrieval.sql`**, затем **`supabase/migrations/003_atomic_world_creation.sql`**. Иначе вкладки «Поиск» и «Персонажи» не смогут получить данные из нового SQL RPC. Весь пакет оставляет старые таблицы `lw_*` нетронутыми.

Windows: `powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1` запускает локальные проверки без коммитов/публикации. GitHub-репозиторий уже создан; для повседневной разработки больше не нужен скрипт первоначальной публикации.

## MCP на Cloudflare Pages (v0.5)

Поскольку сайт уже развёрнут с GitHub-интеграцией, MCP теперь публикуется вместе с ним. Файл `functions/[[path]].js` подключает прежнюю серверную реализацию `worker/mcp.mjs`, а `public/_routes.json` направляет в Functions **только** `/mcp`, `/health` и два OAuth protected resource discovery URL. Статический интерфейс остаётся обычным Pages сайтом. Дополнительный Workers-проект не требуется.

Основной MCP URL: `https://living-world-next.pages.dev/mcp`.

Для полной OAuth авторизации нужно создать отдельного клиента в **Supabase → Authentication → OAuth Server**, а затем добавить **Production** переменную `SUPABASE_OAUTH_CLIENT_ID` в **Cloudflare Pages → Settings → Variables and Secrets**. Использовать старый client_id нельзя: он принадлежит другому проекту. Должны быть включены OAuth 2.1 Server и его корректный Authorization Path `/oauth/consent.html`, а Site URL задан на `https://living-world-next.pages.dev`. Redirect URL берётся из ChatGPT-подключения, не придумывается.

Публичный Supabase publishable key берётся из `public/lib/public-config.mjs`. **service_role не добавлять**. До установки нового client_id MCP отдаёт discovery и метаданные, но закрывает вызовы, читающие личные истории.

Проверка: `/health` должен вернуть `running:true`; `oauth_metadata_ready` отражает только конфигурацию, не фактический вход. До полноценного теста ChatGPT `oauth_e2e_verified:false` остаётся честным.

### Диагностика публикации Functions

Для Cloudflare Pages с нативными Functions необходимо выставить **Build command: `exit 0`** (output `public`). Пустой Build command использовался при чисто статической первоначальной публикации, но не гарантирует обнаружение Functions. Проверить `/release.json` (версия статики), `/health` (JSON от MCP) и метаданные OAuth по `/.well-known/oauth-protected-resource`. Если `/health` показывает HTML входа в приложение, серверный маршрут **не работает**, несмотря на успешный CI GitHub.

## OAuth v0.6

MCP теперь возвращает challenge `401 Unauthorized` при попытке `initialize`, `tools/list` или `tools/call` без авторизации. Метаданные OAuth содержат `openid email offline_access` для обновляемых токенов. Клиенту ChatGPT требуется отдельная официальная OAuth-регистрация в Supabase (старый клиент не изменять).

После регистрации нового клиента его **публичный** UUID можно добавить в `PUBLIC_OAUTH_CLIENT_ID` файла `public/lib/public-config.mjs` через GitHub. Cloudflare автоматически применит изменение. Секреты не нужны. Значение `SUPABASE_OAUTH_CLIENT_ID` из Cloudflare имеет приоритет. Пока клиент не зарегистрирован, доступ к персональным инструментам закрыт.

## Восстановление архива (v0.8)
На главном экране появился импорт резервного файла LIVING WORLD NEXT. Проверяются SHA-256 и причинная структура. RPC `nw_restore_archive` (миграция 006) создаёт **отдельный** мир со всеми ветками, сценами и аудитом правил, не меняя исходный. Для этой версии единая транзакция поддерживает архив до 5000 сцен/30 МБ. Для крупного мира требуется будущая пакетная загрузка.

## v0.9 — чтение и персонажи
На iPhone историю можно читать постранично по 50 более ранних сцен, менять размер текста и межстрочный интервал. В карточке персонажей есть буквальный поиск по всей действующей истории **без ручной разметки**: цитата является подсказкой, не подтверждением события. MCP `get_actor_memory` возвращает отдельно структурированные факты и текстовые упоминания, не смешивая их. Действующие цели, обещания и непримиримая вражда формируют `active_story_drivers` для сценариста, без симуляции поступков в фоне.

## v0.9.3 — облачная синхронизация iPhone
При возвращении на вкладку и периодическом опросе только видимого приложения сравниваются метаданные владельца, ветки и версии правил. Если ChatGPT сохранил сцену, переключили ветку или изменили условия, появляется баннер без сброса текущего текста и места чтения. Загрузка сцены — только по явной кнопке. При несохранённом тексте редактора перед обновлением показывается предупреждение.

## v0.9.4 — ограниченный контекст рассказчика
В промпт больше не вставляется бесконечный JSON всех NPC и прошлых событий. Приоритет: актуальные планы/обязательства, направленные конфликты и доказательства с идентификаторами сцен. Пропущенные записи явно посчитаны; для полного первоисточника используется MCP, поэтому сокращение никогда не означает, что давнее событие не произошло. Длинные последние сцены показываются как маркированные фрагменты с возможностью открыть полный текст.

## v0.10 — игровое время
Вкладка «Время» и MCP `get_world_agenda` читают явно зафиксированные даты сцен, невыполненные намерения и обещания с точными ссылками на первоисточники. Временные оценки осторожны: статус «срок в прошлом» не означает автоматически, что обязательство нарушено, неизвестная дата не придумывается, и события не создаются, пока ChatGPT не пишет сцену.

## v0.10.1 — надёжные архивные выгрузки
При экспорте нескольких тысяч записей со совпадающим временем создания применяется уникальный порядок `(created_at, id)`; повтор строки между страницами вызывает ошибку вместо незаметно неполного архива. Экспорт ровно 50 000 записей поддерживается, 50 001-я обнаруживается отдельным запросом и предотвращает усечение файла.

## v0.10.2 — ограниченный MCP-контекст
`get_world_context` отдаёт компактную доказательную выборку, счётчики записей и ссылки на инструменты точного получения событий. Старые сцены не исчезают: целиком доступны в `get_story_scene`, по персонажу — `get_actor_history`/`get_actor_memory`. Большие литературные сцены в ответе контекста сокращаются с явной меткой и ID.

## v0.11 — экономика
Уникальные предметы и деньги проецируются по записанным событиям действующей ветки. Для денежного перевода используется одно событие money с operation=transfer, actor, counterparty, currency и отрицательным delta. Для предмета: custody_version=1, item_id, actor, action и counterparty при передаче. MCP get_world_economy и экран «Имущество» показывают источники. Старые произвольные действия предметов не устанавливают владельца. Предварительная проверка save_scene работает в MCP, но полноценные SQL-инварианты для всех путей записи ещё предстоит реализовать.

Migration 007 adds the database-side append guard for both ordinary and revised scenes. Not yet applied to the live database. Before applying, run the pure fold tests in `supabase/test_economy_rollback.sql` and exercise a test world including revisions. Existing archives preserve historical annotations. `observe` does not establish custody; `take` records forced taking with a named prior holder, rather than forcing every character to agree.

## v0.12 — состояние персонажей
Необязательные события character со state_patch обновляют независимые свойства героя; остальные поля сохраняют свои источники. Структурированная память не угадывает состояние по отсутствию записей. MCP get_character_state и экран персонажей показывают поля, цитаты и источники по активной ветке. Не требует создания анкет при старте мира.

MCP `get_scene_context` retrieves targeted evidence for up to eight recorded actors and four literal queries in the active branch. The response separates structured events and source snippets, reports incomplete memory, and does not authorize fictional knowledge transfer or automatic plot actions.

## v0.13 — жизнь мира
Вкладка «Мир» и MCP get_living_world показывают места, явно описанный распорядок, последние известные местонахождения и подтверждённые события вне кадра. Записи world_record_version=1 используют стабильный ключ place:<ID> или routine:<ID>, полный актуальный набор полей и дословное evidence. Интервал расписания не означает фактическое присутствие. get_annotation_passages позволяет читать неизменённые фрагменты канонических сцен для будущего доказательного извлечения памяти. Исторический текст не изменяется.

## v0.14 — пакетное восстановление (требует миграцию 008)
Большой архив проверяется в браузере, разбивается на детерминированные SHA-256 пакеты, загружается в приватное стадиирование владельца. Повтор с тем же файлом продолжает загрузку по ID, локально хранится только ID с хэшем, не история. Финальный RPC атомарно создаёт новый мир и выдаёт идемпотентную квитанцию. Незавершённый импорт можно отменить. Миграцию 008 сначала проверить в отдельной БД; реальные пределы времени выполнения больших импортов ещё не подтверждены.

Проверка графа больших архивов использует строгую глубину родителя/ребёнка вместо рекурсивного SQL-обхода длинной цепочки. Глубина — служебная метка пакета, она не записывается в литературные сцены.

## v0.15 — общество и знания
Социальные world events (social_record_version=1) сохраняют группы, членство и независимые линии; знания knowledge_version=1 различают убеждения, подозрения, ложные сведения, забывание и знания конкретного героя. get_social_world/get_character_knowledge читают действующую ветку; вкладка «Общество» показывает источники. Миграция 009 добавляет отдельно от канона предложения памяти: рассказчик извлекает их из старых сцен с точной цитатой через save_memory_notes; get_memory_notes читает их по активной ветке. Не заменяет первоисточник и не переписывает историю. Миграция не установлена, производные заметки не входят в архив v1.

В v0.15.1 планы NPC могут явно обновлять goal/due_at/next_step/obstacle через plan_patch на advance/pause/resume, с отдельными источниками. Открытые сюжетные линии видны рассказчику и режиссёру без автоматического завершения или раскрытия. Литературная диагностика отмечает дословно повторяющиеся концовки.

## v0.16 — долговременные отношения и занятия
Направленные relationship_patch сохраняют независимые эмоциональные поля с источниками. interaction_version=1 в world events хранит эпизоды встреч, конфликтов и совместных действий отдельно от отношений; activity_version=1 — именованные привычки и совместные занятия. MCP get_relationship_history/get_character_activities и экран «Персонажи» читают действующую ветку. Не происходит автоматического улучшения/ухудшения отношений, забывания, завершения занятия или передачи чувств между людьми.

В v0.16.1 появились независимые долговременные последствия (consequence_version=1, world event) с источниками, отдельной фиксацией разрешения и MCP get_world_consequences. MCP save_scene проверяет новые переходы состояния по памяти до записи; прямой SQL и альтернативные ревизии пока не обладают эквивалентной общей проверкой.

## v0.17 — навыки, проекты и слухи
Вкладка «Развитие» и MCP get_character_growth показывают навыки, проекты, передачи слухов и причинные связи. growth_version=1 в обычном world event сохраняет доказанные записи без новых таблиц. Передача слуха не меняет знания получателя автоматически. Причинные связи используют устойчивые world keys и отделяют утверждение от установленных причин. Индивидуальность хранится в отдельных полях character state_patch. Планы и проекты не выполняются по таймеру.

В v0.17.1 проверка альтернативной сцены использует только её предков и фактически сохраняемый префикс. Состояния отменяемого окончания и последующих сцен не переходят в новую ветку. Браузер и MCP выполняют предварительную проверку; SQL остаётся владельцем транзакции и идемпотентности. Полная паритетная SQL-валидация новых типов записей ещё нужна.

В v0.17.2 ограниченный контекст формируется по кругу из категорий памяти, со счётчиками пропусков и источниками. Восстановление браузерной квитанции сравнивает JSON независимо от порядка ключей, но сохраняет порядок событий.

## v0.18 — единый цикл рассказчика
prepare_story_turn объединяет активную память, распорядок, открытые дела, сроки и конкурирующие интересы перед продолжением или переходом времени. Возвращает ожидаемые head/версию правил и кандидатов, не совершает событий. get_world_dynamics и режиссёрский экран показывают социальные связи, учреждения, конкуренцию и изменения. Все записи используют обычный world event с точной цитатой; перенос ресурсов и распространение знания записываются отдельно. После написания сцены используется обычное атомарное сохранение.
