# LIVING WORLD NEXT — архитектура и правила истории

## Основной пользовательский путь

1. Пользователь на iPhone заходит на Cloudflare Pages, один раз подключает Supabase и входит.
2. Вводит ОДНО описание мира. Программа сохраняет оригинал дословно и короткий стартовый маркер, не утверждая, что придуманы несуществующие NPC, расписания или точная дата.
3. Пользователь при желании уточняет мир обычной фразой. Директива классифицируется, но полный текст — источник истины. Не нужно 50 биографий до первой сцены.
4. Пользователь продолжает историю в ChatGPT. OAuth-MCP даёт серверный контекст, последние сцены, проверенные причины, неизвестные вещи явно помечает неизвестными. До первой сцены ChatGPT может создать участников исходя из сюжета, не выдумывая уже сыгранные события.
5. Рассказчик формирует цельную сцену и *после неё* составляет структурные последствия с точными цитатами. MCP проверяет согласованность и записывает сцену по `expected_head`, `request_id` (однократность повтора).
6. Сцена появляется на iPhone; альтернативная ветка связывается с нужным предком, не удаляя старого. «На это» будет интегрировано из ChatGPT на следующем этапе.
7. Через годы чтение идёт по активной цепочке, свёрнутая причинная память подкрепляется точными сценами, а не слепой догадкой модели.

**Нет веб-обёртки поверх OpenAI API и нет отдельного Windows-приложения.** Сама история пишется в ChatGPT. Локальный ПК используется только по необходимости для проверки кода или публикации.

## Две критические психологические ошибки старой модели

**Автономность не равна пассивности.** Люди могут прямо хотеть, требовать, настаивать, проявлять интерес и инициативу, ошибаться и принимать решения. Они реагируют на отказ и ситуацию, но не обмениваются формальными разрешениями на каждом шаге. Интимность между взрослыми персонажами следует реальному контексту отношений, без навязчивого одинакового ритуала. Никаких квот на свидания или секс.

**Вражда не обязана вести к дружбе.** Не существует скрытого положительного рейтинга между противниками. «Спас жизнь» не означает «стал уважать». Гарри и Малфой могут ненавидеть друг друга до конца жизни. Сотрудничество может быть вынужденным, а ненависть — устойчивой. Изменения возможны только при убедительных обстоятельствах и без нарушения прямого авторского запрета.

Отношения направленные (`Гарри→Малфой` отдельно от `Малфой→Гарри`), состояние — словесное и причинное, не число «отношения 70%». Для явно названной пары с фразой «никакого примирения» создаётся дополнительный lock. Неоднозначные формулировки не превращаются в ложную строгую структуру: сохраняются как есть.

## Что чем является

| Слой | Роль | Источник истины |
| --- | --- | --- |
| `nw_worlds` | Исходное описание, название, начальная временная метка, активная ветка | То, что ввёл владелец |
| `nw_directives` | Прямые авторские условия, в том числе запрет примирения | Оригинальная формулировка владельца |
| `nw_branches` | Версии историй | ID текущей вершины |
| `nw_scenes` | Неизменяемые сцены и связанные события | Только фактически сыгранные тексты и ancestry |
| `events` в сцене | Верифицируемые изменения; источник — дословная цитата | Ссылка на сцену/событие, не предположение |
| `public/core` | Общая логика на клиенте и сервере | Тестируемые чистые функции |
| `worker/mcp.mjs` | MCP-мост ChatGPT <-> Supabase | OAuth 2.1 через Supabase Auth, JWT пользователя + RLS; тест подключения ещё требуется |

## Безопасность данных

- Одна таблица — один владелец, RLS для чтения, запись структурных данных только через SECURITY DEFINER RPC с проверкой `auth.uid()`.
- `nw_commit_scene` блокирует мир и ветку, проверяет ожидаемую вершину и версию пользовательских правил. Повтор той же заявки возвращает старый ID, но повтор со сменой содержимого отвергается.
- Аннулированная сцена не удаляется: **она просто не предок действующего `head_scene_id`**.
- Директивы сохраняются как отдельные правила; история фактов не переписывается при смене желания игрока.
- Вложенные файлы и ключи service_role в браузер или публичный репозиторий не помещаются.
- Любая автоматическая память должна различать факт, план, слух, убеждение и неизвестное знание.
- Модель не должна осуществлять внешние события или денежные действия, если они не обоснованы реальным игровым временем и записью в истории.

## От масштабирования до нескольких лет сюжета

Прямая replay-обработка сохраняется простой на первом этапе. Для структурированных событий введена постраничная память по всей цепочке до 50 000 сцен (до миграции 004 — не включена в облаке). Для ещё более долгих миров потребуется контрольный слепок (`checkpoint`) с `scene_id`, хешем, доказательным покрытием и активным lineage, плюс поиск старых первоисточников по запросу. Сам слепок не заменяет сцен и не делает предположения о пропущенных периодах. Ветки никогда не «делят» обновляемый глобальный баланс.

## Почему не копируем весь старый код

Старый `living-world` уже содержит много самостоятельных слоёв PWA, проектов документов, разнообразных директоров, настроек, резервных записей и мостов. Новая архитектура сохраняет **функциональные требования**, но не тащит 180-килобайтный UI и огромный Worker без разбору. Портируются только проверенные идеи и протоколы, по одной функционально законченной системе, но большими интеграционными пакетами.


## v0.4 — автономные цели и доказательная память

- `plan` — подтверждённое **намерение**, не совершённое действие. Переходы start/advance/pause/resume/complete/abandon относятся только к своему актору и `plan_id`. `complete` требует ссылки на реальное событие world/offscreen в той же сцене. Никакого бонуса за «совместную опасность» и механической тяги к примирению.
- `nw_active_memory_page` читает все аннотированные события действующей цепочки с фиксацией `head_scene_id` и делает возможным полное структурированное воспроизведение без пересылки тысяч длинных сцен. Текст неразмеченных сцен **нельзя считать несуществующим знанием**: для достоверного ответа рассказчик ищет первоисточник.
- Каждое `get_story_scene` помечает, существует ли сцена в текущей активной цепочке. Старая альтернативная ветка остаётся доступной владельцу, но не используется как установленный факт.
- Сохранение идемпотентно по всем важным полям, а не только по тексту и событиям. Отправка того же пакета повторно допустима даже после смены ветки. Изменённый пакет с прежним ID отклоняется.
- **Важно:** программная проверка источников не доказывает, что текст психологически верен. Планы NPC и реакции персонажей требуют литературного тестирования с реальной игрой.
